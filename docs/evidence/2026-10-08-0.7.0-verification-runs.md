## Part 1: MPP01 and the challenge's network

**Build:** `5f0d8b2`. The CLI was built from this code (`packages/core/src` and
`packages/cli/src`), four of whose source comments have since been shortened; nothing
else differs.

**Targets:** Wasit's charge fixture (`packages/core/test/fixtures/mpp-charge-server.ts`,
port 3002), which is the official `@stellar/mpp` charge server on `stellar:testnet`; and
the official `@stellar/mpp` charge server configured with `network: "stellar:pubnet"`, on
`127.0.0.1:3099`, which was never paid. Both on our machine; the only chain touched is
Stellar testnet.

**What this is for.** Up to this build, `MPP-01` read the `amount`, `currency` and
`recipient` from the target's challenge, but not its network. The SDK's charge client
takes the network from the challenge and builds its RPC client from it
(`dist/charge/client/Charge.js` in `@stellar/mpp` 0.7.1):

```js
const network = resolveNetworkId(request.methodDetails?.network);
const resolvedRpcUrl = rpcUrl ?? SOROBAN_RPC_URLS[network];
const networkPassphrase = NETWORK_PASSPHRASE[network];
```

`SOROBAN_RPC_URLS` (`dist/constants.js`) has a default pubnet endpoint, and Wasit passed
no `rpcUrl`. So a target asking for `stellar:pubnet` could have a mainnet transfer, for the
amount it chose, signed by the payer key if that account holds mainnet funds. That follows
from the source; it was not run (see Limits). Separately, mppx pays a 402 that follows a
payment again, up to `maxPaymentRetries` attempts, 3 by default
(`dist/client/internal/Fetch.js` in `mppx` 0.8.14).

In `5f0d8b2`, `MPP-01` reads the network the SDK would sign for (one naming none is
testnet, as `resolveNetworkId` does) and refuses any network but the run's. It does so
before anything is signed, both on its unpaid read and on the exact challenge about to be
signed, since mppx requests the target again and pays whatever that answer carries. The
payment goes through the run's RPC endpoint, which must be https, and is made once.

### Offline tests, and each rule broken on purpose

`packages/core/test/unit/charge-network.test.ts` runs `MPP-01` against the official
charge server in process, with an https RPC address on `127.0.0.1` that counts the
connections reaching it. Nothing leaves the machine. Two more tests in
`challenge-parsing.test.ts` cover the parsing. Core: 246 tests, all passing.

```
✔ refuses a stellar:pubnet challenge on a stellar:testnet run before anything is signed
✔ refuses a stellar:testnet challenge on a stellar:pubnet run before anything is signed
✔ refuses when the challenge it is about to pay switches to another network
✔ builds the payment through the run's RPC endpoint, not the SDK's default
✔ refuses an http RPC endpoint, which the SDK cannot pay through, before sending anything
✔ pays once when the target answers 402 again after being paid
✔ reads the network the SDK would sign for
✔ rejects a network that is not a Stellar CAIP-2 identifier
```

Each rule was then broken in the source, one at a time, and the tests rerun:

| Rule broken | Test that failed |
|---|---|
| No check on the challenge about to be signed | refuses when the challenge it is about to pay switches to another network |
| No check on the unpaid read | both "refuses a … challenge on a … run" tests (the target got a second request) |
| mppx's default of 3 payment attempts | pays once when the target answers 402 again after being paid |
| The SDK picks its own RPC endpoint | builds the payment through the run's RPC endpoint, not the SDK's default |
| No refusal of an http endpoint | refuses an http RPC endpoint, which the SDK cannot pay through, before sending anything |
| A challenge naming no network read as pubnet | reads the network the SDK would sign for |
| The refusal reported as the target's failure | refuses when the challenge it is about to pay switches to another network |
| Any string accepted as a network | rejects a network that is not a Stellar CAIP-2 identifier |

## Limits

- The behaviour before `5f0d8b2` was not reproduced live. A run would have built a payment
  through the SDK's default pubnet RPC endpoint, which someone else operates, and signing
  needs a payer account on mainnet. It is read from the SDK's source, and the two
  mutations that remove the network checks show the SDK going on to build the payment.
- A challenge that switches network between the unpaid read and the payment, a 402 after
  payment, and an http RPC endpoint were exercised offline only, against the official
  server in process, not through a CLI run.
- The mutation that lets the SDK pick its own endpoint sent one account lookup, for a
  random key, to the SDK's default testnet endpoint (`soroban-testnet.stellar.org`, also
  Wasit's own default).
- Part 2's Permit2 suite passed on its second run only. The first failed at the public
  facilitator's broadcast, outside Wasit and outside the fixture; a single run cannot tell
  a transient failure from a lasting one.
- The lying paywalls ran on Stellar testnet and Base Sepolia only this time. `wasit serve`
  was run on Solana devnet on 2026-10-05 and on Ethereum Sepolia on 2026-10-06 (those
  days' files say which modes).
- Unreleased: this ran from the branch, not from npm.
